# AWM Standard PPO Baseline v1

The machine-readable source of truth is `configs/ppo_baseline_v1.json`.

## Scope

PPO v1 is a **single-policy, strictly on-policy** learned comparator for the AWM irrigation problem. It is intentionally simpler than RCWA-RL: PPO optimizes a fixed scalar expected-return surrogate and is evaluated afterward under the same Risk Contract v1. It does not contain a distributional yield critic, a CVaR optimizer, a dual variable, budget-monotonic value regularization, population transfer, CPO coupling, or LRMB mechanisms.

The implementation was informed by the read-only LRMB `exp/ppo` branch only for two engineering principles: strict single-policy/on-policy PPO and correct hierarchical gate-plus-active-amount likelihood accounting. AWM has no runtime dependency on LRMB and does not copy LRMB's nitrogen action or study-specific reward.

## Environment and conditioning

- actor observation: the frozen 79D AWM state;
- nitrogen: fixed, never an action;
- postplant water upper bound: 495 mm (W100 policy quota);
- fixed preplant water: 45 mm, included in reported seasonal irrigation but not in the controllable water cost;
- requested protection target: `eta in {0.90, 0.95, 0.98}`, already present as `yield_target_fraction` in the observation;
- training weather: ERA5 2000-2017 only;
- validation weather: ERA5 2018-2022 only;
- station 2023-2025: locked final test and inaccessible to PPO training/selection.

PPO is not trained under separate W60/W80/W100 quotas. It receives the common W100 **upper bound** and learns how much of that controllable water to use. This matches the primary learned-method objective: minimize actual irrigation rather than merely exhaust a prescribed treatment quota. W60/W80/W100 remain important fixed agricultural comparators.

## Hierarchical irrigation policy

The actor represents

\[
\pi(g,z\mid s)=\mathrm{Bernoulli}(g\mid s)\,\mathrm{Normal}(z\mid s)^g.
\]

`g=0` is exact no irrigation. Only when `g=1` is the Gaussian latent active, with

\[
u=\frac{\tanh z+1}{2}\in(0,1),
\]

and the existing WaterBudgetController maps `u` to the currently feasible physical irrigation interval.

The behavior record stored by PPO is the sampled gate and **pre-tanh latent**. PPO likelihood ratios are computed from those sampled variables. Executed DSSAT irrigation, remaining-budget projection, and 0.1-mm execution canonicalization remain separate audit quantities and are never substituted into the behavior likelihood.

Actor architecture:

```text
79 -> Linear 256 -> LayerNorm -> Tanh
   -> Linear 128 -> LayerNorm -> Tanh
   -> irrigation Bernoulli gate
   -> amount Normal mean/log_std
```

The gate output layer is initialized to zero so the initial irrigation probability is 0.5. There is no policy latent because AWM has one conditional policy rather than a population.

The critic has an independent `79 -> 256 -> 128 -> 1` network with the same activation/normalization pattern. Actor and critic parameters are not shared.

## PPO scalar surrogate

The core DSSAT environment remains reward-free. PPO owns a benchmark-specific scalar reward.

At each step:

\[
r_t^{water}=-\frac{I_t}{495}.
\]

At terminal time, same-weather retention is

\[
R=\frac{Y}{Y_{ref}(w)}.
\]

The terminal violation term is

\[
r_T^{viol}=
\begin{cases}
0,&R\ge\eta,\\
-(1+\eta-R),&R<\eta.
\end{cases}
\]

With `gamma=1`, the episode return is exactly

\[
G=-\frac{I_{policy}}{495}
-\mathbf 1[R<\eta](1+\eta-R).
\]

Because `I_policy/495` lies in `[0,1]`, every per-year target-feasible episode has return in `[-1,0]`, while every strictly target-infeasible episode has return below `-1`. This makes target feasibility lexicographically prior to water saving **without a tunable penalty coefficient**.

This is deliberately not called LCVaR optimization. It is a simple target-conditioned scalar expected-return surrogate for vanilla PPO. Formal learned-policy success is still determined by `LCVaR_0.20(R | eta) >= eta` under Risk Contract v1.

## Balanced on-policy rollout

One PPO update collects exactly one full Cartesian cycle:

\[
18\text{ train years}\times3\eta=54\text{ complete episodes}.
\]

Each episode has 125 decisions, so one rollout contains exactly

\[
54\times125=6750
\]

transitions. Every weather-target cell appears once per update; the order is deterministically shuffled from `(training seed, update index)`.

A rollout carries one `policy_version`. After one PPO update the version increments. A rollout generated by an older version is rejected rather than reused.

## Optimizer contract

- learning rate: `1e-4`;
- gamma: `1.0`;
- GAE lambda: `0.95`;
- PPO clip: `0.2`;
- epochs per rollout: `10`;
- minibatch: `450` (15 minibatches per epoch);
- value coefficient: `0.5`;
- entropy coefficient: `0.0`;
- global gradient norm cap: `0.5`;
- full-rollout advantage standardization;
- unclipped critic MSE;
- no reward scaling.

The `gamma=1` choice is part of the reward definition: discounting would make early and late irrigation costs unequal and would break the exact episode-return interpretation above.

## State normalization

The 79D observation is normalized with running mean/variance estimated from **training observations only**. The state normalizer is frozen for validation and later final evaluation. Reward scaling is disabled.

## Seeds and checkpoints

Formal PPO training seeds are preregistered as:

```text
11, 21, 31, 41, 51
```

Each seed runs at most 200 PPO updates. Candidate checkpoints are saved/evaluated every 10 updates. Validation uses stochastic policy actions with fixed evaluation draw seeds and no gradient updates.

Checkpoint selection follows `awm-learned-method-evaluation-v1`: one checkpoint per training seed must jointly serve all three eta levels. Seeds are independent replicates and may not be cherry-picked.
